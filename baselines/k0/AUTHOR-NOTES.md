# K0 author notes

- Inputs read: the prompt and the four contract schemas (S0/S1 × home/desk) only. No data, no web. Triggers were written in one pass from the schemas and never tuned; the tests are my own utterances.
- `triggers_S*.json`: up to 15 phrases per tool. The desk tools share one list across S0 and S1. The S1 home lists add the synonyms that S1's descriptions name (lounge, roomba, wemo, violet, daylight, base). The extractor loads the union of both files and uses it for two things only: the anchor for "nearest to the trigger", and the start of a free-text span.
- Enum gazetteer. It matches each enum value, the value with `_`/`-` read as spaces, and synonyms parsed out of the parameter's own description: `value (a, b or c)` and `'value' means X`. It also matches any 1–3-word spelling in the tool or parameter description that normalises to the value, which is how S0's `todo` picks up "to-do". The tool description is not mined for parentheticals, because there they list verbs (e.g. "(switch on, switch off, turn out)") and would map on to off. Matches are word-bounded, and a match inside a longer match is dropped (so "warm white" beats "white" and "hallway" beats "hall").
- When several enum values match: first, one immediately followed by the parameter's own noun ("shopping list") wins; this is my addition, so that "add packing tape to my shopping list" works. After that, the nearest to the trigger match wins, and with no trigger, the earliest.
- Polar lexicon (mine, fixed): on/off cues (turn on, switch off, turn out, out, kill, unplug…) and vacuum cues. The vacuum cues have a priority: dock (dock, base, home, charger) > stop (stop, pause, halt) > start (start, run, clean, vacuum, hoover), so "stop cleaning" is stop. Cues only map onto values the schema actually has. Polar parameters are extracted before the others.
- Numbers: digits and English number words from zero to a hundred. The unit is "%"/"percent" when the description says percent. Preference order is a number carrying the unit, then one after "to"/"at", then the nearest. Number words the schema itself equates with a value ("full or max is 100, half is 50" in S1) are accepted. S0 declares none, so "full brightness" refuses there. A non-integer for an integer parameter, or a value out of range, refuses; nothing is clamped. Relative words ("brighter", "a bit") never produce a value, because no schema has a matching enum.
- `control_vacuum.room`: S0 says "Only used with action 'start'". That clause is parsed, and room is dropped for other actions.
- Times, to HH:MM: `7:30`, `7pm`, `7 o'clock`, number words with am/pm, half past / quarter past / quarter to, noon/midnight, bare `at 7` / `at seven thirty` / `at 1930`, and `in N minutes/hours` resolved against the fact-line clock. A bare hour with no am/pm is taken literally (at 7 → 07:00) unless tonight/this evening/afternoon (pm) or this morning (am) appears. An hour or minute out of range (25:00, 13pm) refuses. A relative time never sets a date, because the schemas' own "next time it comes round" rule already covers it.
- Dates, to YYYY-MM-DD: ISO dates, today/tonight, tomorrow, the day after tomorrow, weekday names (the next occurrence strictly after today, so "Wednesday" said on a Wednesday is a week out), in N days/weeks, month-day in either order (rolls to next year if already past), "the 12th" (this month, or next month if past), and m/d under en-US (d/m otherwise). An impossible date refuses. Without a fact line, relative dates and times give no value.
- Free text (item, text): the span after the longest earliest trigger, with the tokens used by other arguments blanked out. The first non-empty piece is kept after stripping a leading to/about/that/me/please and a trailing preposition or determiner (to, on, off, from, at, the, my…). When the trigger is not at the start ("milk on my shopping list"), the text before it is tried first. Internal prepositions ("go to the gym", "two bottles of milk") are kept.
- Optional arguments with no evidence are always omitted. That includes those with a declared `default` (S1 room, reminder time) and S0's prose "Defaults to …". Nothing is guessed.
- `split` splits on ", then", ";", " and ", " then " (case-insensitive) and drops a leading "then". It splits naively, so "salt and pepper" or "an hour and a half" also split. That is the declared list working as specified.
- Known weak spots I did not patch: time and date phrases that stay in reminder text when no clock time is found ("in the morning"); ordinal words ("the twelfth"); "all the lights" in S0 (S0's schema does not name it, so room is omitted).
